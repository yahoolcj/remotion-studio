你好，今天我们来聊一聊 SemVer，也就是语义化版本号规范。

一个标准的版本号由三部分组成，分别是主版本号、次版本号和修订号，用点号分隔。格式就是 MAJOR 点 MINOR 点 PATCH。

首先是主版本号。当你做了不兼容的 API 变更时，就需要递增主版本号。比如 React 从 17 升到 18，引入了并发渲染，这就是一个 Breaking Change。

然后是次版本号。当你新增了功能，但保持向后兼容时，就递增次版本号。比如从 1.3.0 升到 1.4.0，旧代码完全不受影响。

最后是修订号。修订号专门用来修复 Bug，不会添加任何新功能，你可以安全地升级。

除了这三个数字，还可以添加扩展标识符。通过连字符可以标记预发布版本，比如 alpha、beta、rc，表示这个版本还不够稳定。通过加号可以附加构建元数据，但它不影响版本比较。

说到版本比较，规则也很简单。先比主版本号，再比次版本号，最后比修订号。预发布版本总是低于同号的正式版。

最后总结一下。主版本号代表破坏性变更，次版本号代表新增功能，修订号代表 Bug 修复。掌握了 SemVer，你就能更好地理解依赖管理和版本升级。
